One Finance UX

A thin on-prem outcome layer. It subscribes to facts the bank already produces and answers one question per close: Ready, Blocked, or Delayed — and why.

Subscribe. Fold. Show one light. Do not replace Motif or Helix.
Motif · CATS · Helix→Facts→Hub fold→Ready / Blocked→One board
  • Kafka, SNS, Redis, Airflow, Lambda move or schedule work. They are not this product.
  • Phase 1 runs as-is: HTTP ingest, H2, three processes. No new cloud bill or broker licence.

Q · Kafka / IBM MQ / ActiveMQ

Use the bus. Do not confuse it with the fold.

A message on motif.book.lifecycle proves the producer wrote and the consumer read. FOBO still needs distinct books, a named blocker, and one Helix POST with a run id.

Keep the broker. Adapter is thin. Browser never touches the bus.
Motif→Kafka / MQ topic→Thin adapter→POST /api/events→Fold → Helix once
  • Kafka can store 300 MASTERBOOK_READY. The hub counts distinct keys, then POSTs Helix once.
  • IBM MQ and ActiveMQ are the same category — a good adapter behind the same API. REST + SSE only in the browser.
